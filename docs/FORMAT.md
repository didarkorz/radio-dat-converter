# Поддерживаемый формат DAT

Это описание реализации `convert_dat.py` и наблюдений по включённым образцам, а не официальная спецификация производителя.

## Старый файл

Каналы расположены в начале файла: одна CSV-строка на канал, 18 полей. Чтение прекращается после начала таблицы при первой пустой строке или строке без запятых. Максимум — 16 каналов. Файл читается как Latin-1, чтобы не зависеть от кодировки его оставшейся части.

Нумерация полей в таблице начинается с 1:

| Поле | Использование |
| --- | --- |
| 1 | Частота RX |
| 2 | Частота TX |
| 3–4 | Индексы тонов, читаются, но не используются при кодировании |
| 5–16 | Старые параметры; используется только поле 9 |
| 17 | Тон RX в текстовом виде |
| 18 | Тон TX в текстовом виде |

Поле 9 преобразуется в байт флага: строка `1` даёт `EB`, любое другое значение — `EF`. Семантика этого флага не установлена.

## Новый файл

Первая строка — заголовок, который копируется из шаблона. В образце это `[FSF008_Analog_Redio]`.

Остальные строки содержат текстовые шестнадцатеричные записи:

```text
57 AA AA 08 DD DD DD DD DD DD DD DD
```

`57` — ожидаемый тег, два байта `AA AA` — адрес (старший байт первым), `08` — длина блока, далее восемь байтов данных. Скрипт собирает образ памяти, заменяет записи каналов и выводит образ блоками по восемь байтов с окончаниями строк CRLF.

Шаблон должен быть полным, с последовательными блоками от адреса 0, без пропусков и повторов. Текущий парсер не проверяет это условие: пропуски будут заполнены нулями, а при повторении адреса будет использован последний блок.

## Запись канала

Каналы начинаются по адресу `0x10`. Одна запись занимает 16 байтов; 16 каналов занимают область `0x10–0x10F` включительно.

| Смещение внутри записи | Размер | Значение |
| --- | --- | --- |
| `0x00` | 4 байта | Частота RX |
| `0x04` | 4 байта | Частота TX |
| `0x08` | 2 байта | Тон RX |
| `0x0A` | 2 байта | Тон TX |
| `0x0C` | 1 байт | Флаг `EB` или `EF` |
| `0x0D` | 3 байта | `FF FF FF` |

### Частоты

Восемь десятичных цифр без точки представляются в упакованном BCD с младшим байтом первым:

```text
435.32500 → 43532500 → 00 25 53 43
```

### Тоны

Двухбайтовые значения записываются младшим байтом первым:

| Тон | Правило | Пример байтов |
| --- | --- | --- |
| `OFF` | `0xFFFF` | `FF FF` |
| CTCSS | `0x89FF − частота_тона_в_десятых_Гц` | `127.3 → 0x8506 → 06 85` |
| DCS normal | Префикс `D` и три цифры кода | `D371N → 0xD371 → 71 D3` |
| DCS inverted | Префикс `C` и три цифры кода | `D371I → 0xC371 → 71 C3` |

Для DCS принимаются цифры `0–7`; суффиксы `I` и `R` обозначают инверсию. При декодировании инверсия всегда выводится как `I`. Выбор префиксов `D`/`C` основан на наблюдениях в новом CPS, отмеченных в исходном коде.

## Границы переноса

Заменяются только записи каналов, присутствующих в старом файле. Остальные байты берутся из образа шаблона. Содержимое старого файла после таблицы каналов игнорируется.

Поэтому корректное преобразование частот и тонов не означает переноса всех функций старой рации. Для другой структуры памяти потребуется отдельная адаптация.
